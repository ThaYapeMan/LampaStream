# Players implementation decisions

- **Routes:** `/players` is canonical. `/latency` and `/virtual-players`, including their old hash bookmarks, redirect with `history.replaceState`. Existing `#players` bookmarks still work. A `player` query selects a virtual-player ID, receiver MAC or followed-player MAC. Browser Back/Forward follows navigation. Now Playing's Player settings link includes the current timing MAC.
- **Other timings:** saved latency entries are matched by case-insensitive MAC against virtual players' current listening targets. Manual LMS uses its configured follow target; AirPlay uses its own receiver MAC. Active LMS sync-group mode uses the preview's detected target. Inactive sync groups have no observable current target and do not claim the retained manual target. Unmatched entries appear under Other timings, including timings retained after a virtual player is deleted.
- **Components and styling:** the approved mockup was opened in Chromium. Its list–detail grouping maps to a responsive Tailwind grid with a 340 px desktop list, existing Card, Badge, Button and Dialog components, and the existing dark-theme tokens. Identity, timing and Details are three cards. The timing card shares LightTiming's state calculation, save handlers and fine-tune behaviour with Now Playing; its Players presentation uses the mockup's concise explanations and segmented control. No mockup CSS was copied. AirPlay retains the approved mockup's line-style receiver glyph. The exact embedded LMS PNG is used at 17 px and 22 px without further changes.
- **Backend:** no backend change or new endpoint was needed. Virtual-player, coupling and latency APIs refresh every two seconds; active runtime status reuses App's existing preview websocket. Measurement, timing, LMS commands, AirPlay processing and yeney-core are unchanged. Unknown or inactive engine/receiver facts are not inferred from a saved timing.
- **Delete:** the existing in-page confirmation dialog handles both operations and surfaces errors. Deleting a virtual player calls only the virtual-player delete API and preserves all timings. Deleting Other timings calls only the latency delete API. Cancel performs no deletion. Existing player and latency editors are reused.
- **Selection and Now Playing:** a roving-tabindex listbox supports Up/Down, Home and End. The selected row is remembered in localStorage with exceptions handled, including initial deep links. The first LampaStream player is the default; the first saved timing is used when no virtual players exist. Show on Now Playing returns to the active session without changing couplings or starting playback.
- **Omissions:** the mockup's explanatory notes card is deliberately excluded as requested. No new measurement logic or playback selection was introduced. The two unrelated research files remain untouched. Icon permission remains for the owner to confirm before public release, as recorded in the design README.
- **Validation environment:** FFTW development and runtime Debian packages were extracted under `/tmp` to build the existing cavacore library and wheel without changing system packages. Initial native-check failures were caused by missing build prerequisites. Browser selectors were updated to distinguish player options from the existing editor-mode select. The affected browser tests passed individually before the full final suite. The wall-clock cavacore processing test failed during concurrent frontend/backend work and passed when rerun alone; the backend suite is then rerun without concurrent builds.
